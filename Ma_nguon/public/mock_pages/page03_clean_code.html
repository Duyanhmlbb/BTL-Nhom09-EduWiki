Clean Code và Nghệ thuật Tái cấu trúc Mã nguồn trong PHP

Viết mã sạch (Clean Code) không chỉ giúp ứng dụng hoạt động ổn định mà còn giúp đồng nghiệp và chính bạn dễ dàng đọc hiểu, bảo trì trong tương lai.

1. Nguyên tắc đặt tên có ý nghĩa

Tên biến, hàm và lớp nên thể hiện rõ mục đích sử dụng. Tránh các tên viết tắt tối nghĩa như $data, $temp, $arr.

// Chưa tốt:
function get_u($i) { return db_query($i); }

// Viết mã sạch:
function findUserById(int $userId): ?User {
    return UserRepository::findById($userId);
}

2. Hàm chỉ nên làm một việc duy nhất (Single Responsibility)

Một hàm chỉ nên đảm nhận một trách nhiệm duy nhất và thực hiện trách nhiệm đó một cách tốt nhất. Nếu hàm của bạn dài hơn 20 dòng hoặc có quá nhiều câu lệnh rẽ nhánh, đó là dấu hiệu cần tái cấu trúc.

3. Nguyên tắc DRY (Don't Repeat Yourself)

Không lặp lại mã nguồn. Khi phát hiện các đoạn logic giống nhau xuất hiện ở nhiều nơi, hãy trừu tượng hóa chúng thành các hàm tiện ích hoặc lớp dùng chung.

Mã nguồn sạch là tài sản lớn nhất của một dự án phần mềm lâu dài. Đầu tư vào chất lượng code hôm nay là tiết kiệm thời gian gỡ lỗi ngày mai.
